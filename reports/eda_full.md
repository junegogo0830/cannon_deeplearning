## 1. 데이터 로딩

- `os.walk`로 `data/raw` 전체를 훑음 (숨김 파일 포함)
- 전체 파일 **47,270개** = jpg **47,267** + 비-jpg 3개 (`T595NP_층별일람표_2.xlsx`, `.gitkeep`, `NG - 바로 가기.lnk`)
- 파일별로 경로 구조를 분류: 기종, 제품 폴더(파일 바로 위, NG 제외), NG 여부, 파일명의 스텝 번호, 정상 깊이 여부
- 정상 깊이 = `기종/제품/step_N.jpg` (3단) 또는 `기종/제품/NG/…jpg` (4단). 이 밖은 "비정상 깊이"로 기록

**해석**: 파일 수 47,267은 팀원 보고서와 일치. 우리 전처리·학습 파이프라인은 정상 깊이만 읽으므로, 아래 2절의 중첩 폴더 30장은 현재 파이프라인에서 제외된 상태.

## 4. 이상치 확인 (밝기 · 선명도 · 채도)

- 측정: 그레이 평균 밝기, 256px 축소 후 라플라시안 분산(선명도), HSV 채도 평균 — 전수 47,267장
- 기준 분포: **루트 정상 사진만**, 기종·스텝별. 참고 20장 미만 그룹은 보류 (팀원과 같은 운영 규칙)

## 5. NG 사진 대조 — 파일명 스텝이 사진 내용과 맞는가

**방법**: NG 사진을 같은 제품의 루트 사진 전부와 비교 (128×96 그레이, 정규화 후 상관계수). 가장 비슷한 루트 스텝이 파일명 스텝과 같은지 확인. 기준선은 같은 기종·같은 스텝의 다른 제품 30장과의 상관.

**결과**: 12장 중 **6장만 파일명 스텝이 가장 비슷한 루트 스텝**과 일치.

**해석**:
- **강한 증거 1개**: 2EQ16580의 두 번째 `step_9` NG 사진은 루트 `step_10`과 상관 **0.98** — 사실상 같은 사진. 즉 **NG 폴더의 파일명 스텝과 실제 사진 스텝이 다른 경우가 있음**. 팀원이 말한 N04 유형과 같은 문제
- **약한 증거**: 상관계수는 조명·구도 차이에 민감해서 저대비 표면(흰 플라스틱)에서는 변별력이 낮음. 기준선(다른 제품 같은 스텝)도 0.3~0.8로 넓게 퍼져 있음. 따라서 "일치 6장/불일치 6장"을 그대로 신뢰할 수는 없음
- 2EQ16580 step_9 첫 번째 NG는 이전 대화에서 전원스위치 사진으로 확인했고, 루트 step_9도 전원스위치라 이 파일은 파일명대로 보임. 같은 제품 안에서 **NG 파일 두 장이 서로 다른 스텝 내용**을 담고 있음

## 8. 라벨 상태 (확정 여부)

| 항목 | 상태 |
|---|---|
| 루트 `step_N.jpg` = PASS | **미확정** (재촬영·수리 후 최종본이라는 가정만 있음) |
| NG 폴더 사진 = FAIL | **미확정** — 5절에서 파일명 스텝과 사진 내용이 다른 사례 확인 |
| 한 제품 NG 여러 장 = 모두 불량 | **미확정** (2EQ16580: NG 4장, 그 중 1장은 다른 스텝 내용) |
| 제품 FAIL = 스텝 하나라도 FAIL | 팀 합의(최병준·정채환 대화)에 따른 작업 가정 |

조교님께 확인할 질문 (팀원 제출 내용 + 이번 발견):
1. NG 폴더 사진의 스텝 번호와 실제 사진 내용이 다를 수 있는지 (2EQ16580 step_9 두 번째 사진 = step_10 사진)
2. NG 폴더 안 사진은 불량 스텝만인지, 같은 제품의 다른 PASS 스텝도 섞였는지
3. 루트 사진과 NG 사진의 관계 (수리 전/후, 재촬영 여부)
4. 체크포인트 번호와 스텝 번호 대응 규칙 (step_0 = 바코드, 전원스위치 = step_9 등 불일치)
5. 중첩 폴더 2개(2EQ16160, 2EQ16973)를 독립 제품으로 볼지
